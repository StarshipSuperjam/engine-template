## Decision

_Amended 2026-08-16: Issues are intake; a Build's plan is session-held, durable only through promotion (eADR-0041)._

_Amended 2026-08-17: the draft-PR-is-the-claim lifecycle is the single-Build view of the multi-writer integration lifecycle fixed by eADR-0042. "Green" authorizes merge only as an integration candidate re-proven against the current canonical tree, not as a candidate green against its starting base; the operator's merge remains the sole unbypassable wall across both views._

_Amended 2026-08-23, deliberately narrowly, for the Project Manager substrate (eADR-0044). A durable local plan library now EXISTS in the engine and is UNCONSUMED: nothing in the Build path reads it, `plan bind` still takes the plan the session hands it, and promotion to a writable Issue remains the only durable plan transport. Everything this record says about where a Build's plan lives therefore still holds exactly as written. What this amendment corrects is one phrase in Significance: "never a durable engine-private ledger" is no longer true of the engine as a whole. It remains true of the BUILD's own state, which stays machine-local, non-durable and authority-free — that is the claim this record actually rests on, and it is unchanged. The plan-authority half is expected to move when the Build Coordinator is cut over to sealed-handoff entry; until that lands and amends this record again, this record governs, and a merged tree in which the library exists but nothing reads it is not self-contradictory._

_Amended 2026-08-24, for the Build Coordinator cutover the amendment above said was coming. The plan-authority half has now moved, so the paragraphs below are corrected rather than merely scoped. A Build's plan is no longer session-held and no longer promoted: it is authored in the Project Manager, sealed there, and read from the durable local library at `plan bind`, which is the ONLY way a plan enters a Build. `plan promote`, `handoff export --publish` and the `--source issue` entry path are gone, so no path publishes a plan to GitHub at all, and "a build Issue carrying a promoted plan" names a thing this engine no longer produces. The Issue keeps exactly the role this record always gave it — intake, and the intent record the pull request closes — and for unattended work it is the AUTHORIZATION, which `plan bind` now proves corresponds to the sealed plan's own recorded intent rather than assuming it. What this costs is stated plainly, because it is the real price of the change and this record is where it belongs: cross-session recovery is now workstation-only. A cold session on another machine cannot read the plan, because the library is local and gitignored; the pull request no longer carries a promoted copy to recover from; and the merge surface's account of what was agreed cannot be externally verified against the plan, only against the PR body that describes it. That was accepted deliberately under the single-workstation trust model (eADR-0044), and the honest consequence is that the operator's read of the pull request — not a second machine's ability to re-derive the plan — is what stands behind a merge. The Significance paragraph's "never a durable leg, never plan authority" is corrected below in the same spirit: it was one sentence about two different things, and only one of them changed._

_Amended 2026-08-25, for the Build's own execution state. The one claim the two amendments above kept protecting — that the coordinator's snapshot is machine-local, NON-DURABLE and authority-free — is corrected here, because the non-durable half was refuted by use. A Build was killed mid-flight and every piece of coordinator evidence it held went with it: approval, review receipts, findings and their dispositions, progress. It was reconstructed by hand. Evidence that a restart can take is not evidence an operator can rely on, and "expected to die with the machine" turned out to describe a defect rather than a discipline. So the snapshot is now DURABLE, and the OS-temporary-directory refusal that enforced the old claim in code is deleted rather than quietly relaxed. It lives beside the sealed plan that bound it, in the same local, gitignored, owner-only library, one snapshot per plan; a second Build of the same plan displaces the first only through an explicit verb that keeps the displaced snapshot. What is deliberately NOT changed is the half this record actually rests on: the snapshot still carries no authority. The plan is the authority, a snapshot that disagrees with the sealed plan still loses, and durability buys survival, not standing. Two costs are stated rather than discovered later. Build evidence now persists on disk for as long as its plan folder does, including reviewers' local-only private notes, under the same workstation-only trust model the library already rests on (eADR-0044); and because the library is per-workstation, durable state does not make a Build resumable on another machine — the restart it survives is a restart of this one._

Build work is carried by native git/GitHub records and never by an invented artifact of its own. The draft pull request is the claim and the change surface: it holds what has been built — the opening claim, the integrated commits, the human merge gate, and the contract narrative — and it is the one record every Build has. A GitHub Issue is work intake: a problem or need ready to be taken up for planning — never the plan itself, and never created merely because a Build exists. When an originating Issue exists it remains the intent record the pull request closes at merge — nothing more.

The Build's plan is not a GitHub record at all. It is authored, deliberated, reviewed and SEALED in the Project Manager's durable local library, and a Build enters on that seal: `plan bind` reads the sealed plan from the library and refuses anything else. No path publishes a plan to GitHub — not as a promoted Issue block, not in a pull request body — so nothing about an Issue is changed by a Build existing. Cold continuation re-anchors on the sealed plan record's own digest and fails closed when that record is missing or has moved, which is the durable anchor promotion used to provide; the cost is that recovery is workstation-only, stated in the amendment above. For unattended work the Issue remains the AUTHORIZATION and the sealed plan is the PLAN AUTHORITY: neither substitutes for the other, and bind proves the supplied Issue is the one the plan's recorded intent names. How a plan is deliberated, approved, reviewed and sealed is owned by the Project Manager's decision record (eADR-0044); how a sealed plan is bound and executed is owned by the coordinator's behavioral contract (eADR-0041).

There is no separate claim artifact, no reserved slot number, and no close ritual; a build is done when its PR is submitted, and the only unbypassable wall is the operator's merge of the protected branch.

## Significance

This fixes where build state lives. Durable build state stays in native legs that git and GitHub already keep — git itself and the pull request, including the bounded handoff block its body may carry. The coordinator's own snapshot is machine-local working evidence that carries no authority: **never plan authority** (eADR-0041). That phrase was once one sentence about two different things — durability and authority — and the amendments have separated them one at a time. About the PLAN, "never plan authority" became false in 2026-08-24 and deliberately so: the plan lives in a durable engine-private library, it IS the authority, and it is the one artifact this record concedes to an engine-owned store — because the alternative was a plan the operator could not keep across a reboot, which is the failure that bought the concession. About the BUILD's state, the authority half is unchanged and is the claim this record actually rests on; the durability half was dropped on 2026-08-25, for the reason the amendment above gives. What did not move is the rest: no receipts and no progress ledger become plan authority by sitting beside a plan, and an unreachable GitHub still bounds only cold resume rather than the work in front of you.

Later work must respect that an Issue is intake and never a plan container by identity — a session holding an approved plan opens its draft PR and builds, filing no Issue for the work it is doing now; promotion is the only path plan content takes to an Issue, and only for cold continuation; and nothing manufactures a close ceremony around the merge. Anything that reviews a build attaches its judgment to the PR contract (eADR-0021), never to a new artifact; the merge is the sole wall and every nudge before it is honestly a nudge.

## Rationale

A close mechanism that invents its own claim object — a reserved subject, a slot to allocate, a close-shape to police — spends real effort guarding a ritual instead of shipping the change, and that friction compounds into a spiral where closing work costs more than doing it. The native records already encode every state a build passes through: open, committed, submitted, merged. The two questions a build answers split cleanly without a second bookkeeping surface: what has been built is the PR and its commits; what is not yet built is the plan, which lives with the build and becomes a GitHub record only when recovery genuinely needs one. That keeps each record single-purpose — the PR carries the change, an Issue carries a problem awaiting work — lets a cold session reconstruct where a build stands from git plus the promoted plan when one was needed, and keeps the operator's merge the one decision that matters. The cost paid is honest degradation: when GitHub is unreachable a durable plan is unreadable, so cold continuation fails safe rather than guessing, while same-session work continues.

## Anti-choice

The rejected alternative was a dedicated claim artifact — a reserved-subject commit or allocated slot that announces and tracks the build as its own object, with a structured close ritual to retire it. It lost because that machinery is precisely the friction it claims to manage: every reserved subject needs an allocator, every close-shape needs an allowlist to police, and the apparatus grows faster than the work it wraps, turning closing a change into its own project. Rejected with it is the softer ceremony of a tracking Issue minted for every Build: it duplicates the record the PR already is, teaches that an Issue is a plan, and buys durable recovery only for builds that never needed it — promotion covers the rare Build that does. The native records carry the same states with none of the bookkeeping, so an invented artifact buys nothing the PR — and, for cold continuation, a promoted plan block — does not already give.
