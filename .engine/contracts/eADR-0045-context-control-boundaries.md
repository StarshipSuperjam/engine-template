## Decision

The engine does not initiate, schedule, or configure context compaction, and does not estimate how full a context is. It treats compaction as something that happens TO a Build and guarantees recovery from it: every Build-mutating coordinator verb verifies the running session against the durable snapshot before it writes, unconditionally, and refuses by name on a mismatch. A post-compaction hook injects a re-grounding pointer built from a closed allowlist, and is advisory. It reacts to a compaction; it does not record that one happened, and nothing in the engine keeps a history of them. Separately, the boundary between sealing a plan and building it becomes a question that must be answered: the seal renders a hand-back asking which model and reasoning effort the BUILD is to run on, and Build entry refuses until the bind carries both. There is no override, because the answer is itself the operator's agreement to begin. Everything else about that boundary — settling durable facts, compacting or clearing — is ceremony, and is described as ceremony wherever it appears.

## Significance

This settles which half of the context problem the engine owns. It owns RECOVERY, and it owns it with a mechanism that cannot be weakened by the unreliability of any signal: verification does not ask whether a compaction occurred, because the only thing that could answer is a fail-open hook. It does not own PREVENTION — no engine-written auto-compact setting in any scope, no engine-initiated compaction, no token estimation — and the operator's own threshold stays the operator's, because a project-scope value would silently outrank a user-scope one they set themselves. The consequence a later change must preserve: any new coordinator verb is verified by default, since the exempt set is a small enumerated list and everything absent from it is checked. That enumeration is itself load-bearing and was got wrong once — a whole command family was exempted at a stroke, so a mutating verb added under it would have inherited the exemption instead of being granted one.

TWO VERBS ARE CARVED OUT, and the carve-out is stated here rather than left to be discovered in the exemption set, because it is a real hole in the word *every*. `state migrate` and `state supersede` mutate, and neither is verified. Both exist to deal with a snapshot the running session does NOT match — supersede sets aside one bound to a worktree that may be gone, migrate rehomes one that was never bound here at all — so gating them on the match would deadlock the exact situation they exist to unstick. What it costs: an operator running `state supersede` from the wrong worktree is not stopped. That was judged the better trade against a recovery path that cannot run when it is needed, and it is closed by REASON rather than by mechanism, which is the weaker kind of closure and is named as such. A future change that widens this set inherits the obligation to argue the same way.

The hand-off's honesty is equally load-bearing, in the opposite direction from what it first looked like. The gate can require that an answer was given. It cannot prove the operator was genuinely asked, that any context was cleared, or that the model named is the model running. Every prose surface describing it says so. A future change that tried to close that gap by DETECTING the operator's break rather than requiring their answer would be re-making the mistake recorded below.

## Rationale

Three facts about the platform, verified rather than assumed, force the recovery shape. No mechanism lets a model initiate compaction in an interactive session, so an engine that promised to compact on your behalf would ship dead code. The auto-compact threshold is operator-configurable at user scope and the harness caps it at the model's window, so the engine has nothing useful to add and something real to break. And `SessionStart` with the `compact` matcher is the one point at which anything can reach a freshly compacted session, which is why re-grounding lives there and not on the pre-compaction event, which cannot inject at all.

The unconditional scope of verification is the load-bearing choice, and it was made against the cheaper one. Verifying only when a compaction was observed would have been a smaller change and would have read as equivalent. It is not equivalent: the observation comes from a hook that fails open by law, so the guarantee would have been the hook's reliability wearing a guarantee's name. Running always costs three cheap reads and makes the post-compaction path and the ordinary path the same code, which is also the only way the recovery path gets exercised by every Build rather than by the rare one that happens to compact. Verification reads and never writes — a write would bump the snapshot revision under a compare-and-swap guard the verb is about to hold, and the check protecting the Build would be what wedged it. It writes nothing anywhere else either: a durable count of the times it held would be a record kept for its own sake, and the guarantee is the refusal, not the tally.

The hand-off is a required answer rather than a prompt because a prompt at the seal is exactly what the old ceremony already implied and nobody took. What made it skippable was that nothing downstream noticed. A refusal at bind is noticed. Requiring the ANSWER rather than detecting a boundary is what makes the refusal unbypassable without being coercive: there is no flag to learn, so a session cannot route around the asking, and an operator who genuinely means to continue pays one short sentence rather than a recorded escalation.

## Anti-choice

The strongest rejected alternative was an engine-managed auto-compact threshold rendered into project settings, which a four-lens panel refuted from three directions at once: the settings-wiring seam is closed and has no scalar-key path, a project-scope value would silently preempt the operator's own user-scope setting, the value would sit outside the operator tuning lane, and it was required by neither the boundary nor the recovery conditional. A one-time user-level recommendation replaces it and the engine writes nothing.

The alternative rejected latest, and the one this record most exists to warn about, was BUILT and then removed: a boundary detector. Build entry would refuse unless it could prove the conversation had actually broken since the seal — by comparing the binding session's identity against the session recorded as having sealed the plan, and by reading an append-only ledger of compactions written by the re-grounding hook — with an explicit operator override for the case it could not prove. It worked. It was still wrong, on the operator's own reading of what they had asked for: they wanted a stop that offers them a choice, not an engine that adjudicates whether they had taken a break. Detection bought nothing the required answer does not buy, and it cost a compaction ledger, a sealing-session marker, an override flag, an escalation path published in the pull request, and a status readout — machinery whose only consumer was the detector itself. A gate that infers consent from a boundary it sniffed is also weaker than one that simply requires the answer, because inference can be satisfied by accident and an answer cannot. The compaction ledger is gone with it: nothing reads a history of compactions, and one kept anyway would be bookkeeping for its own sake.

An earlier variant of that same detector is recorded too, because its appeal survives its refutation: proving the boundary from the live-session marker boot writes. That marker is keyed to the repository root of the checkout the reading code runs from, and Build entry runs in the build worktree, which is never the root boot stamped — so it reads as absent every time. A gate resting on it would refuse every bind, and a gate that always refuses is a gate everyone learns to override.

Also rejected: an MCP control bridge letting the engine initiate compaction, refuted by the absence of any such platform mechanism; prepared boundary receipts every N integrations, refuted because an always-current snapshot makes a receipt prepared at integration N useless to a compaction landing mid-node later, and the snapshot is the recovery authority; an attended pause at a utilization threshold, rejected because native compact-and-continue before the drift zone is strictly better than stopping and keeps unattended runs alive; a second consent ceremony at the boundary beside the existing bind gate, rejected because that gate already refuses without a recorded operator decision and a second ceremony would drift from the first; and surfacing the recorded model and effort back to the operator in status and in the pull request, rejected on their own instruction — they chose it, and reading their choice back to them at every later surface is noise wearing disclosure's clothes.
