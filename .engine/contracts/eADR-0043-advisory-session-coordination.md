title: Cross-session worker coordination is advisory; the payload is durable and the doorbell is live

## Decision

Active Engine worker sessions may coordinate while work is in flight — breaking-change warnings, overlap
warnings, prerequisite handoffs, bounded status, integration and revalidation notices — under one governing
law: **live communication may reduce latency and rework, but Engine correctness, authority, consent, and
future-session truth never depend on a message being delivered.** Git, GitHub, the Engine's receipts and
contracts, the settled specification, and the serialized-integration machinery (eADR-0042) remain the sole
authorities. This capability makes that lifecycle cheaper and less conflict-prone when a runtime supports
live messaging; it never replaces a correctness property of it.

Seven properties bind every part of this capability:

1. **Payload durable, doorbell live.** The system of record for a coordination signal is a typed,
   digest-verified, machine-marked **notice** kept in one Engine-maintained comment on the GitHub work item
   it concerns — platform-stamped with actor and time, so the audit trail is a property of the platform, not
   of the Engine's honesty. The live lanes (a runtime's own cross-session messaging) carry only a
   fixed-format one-line **poke** pointing at that durable notice. A held, refused, dropped, forged, or
   stale live message can never become truth.

2. **No free-prose slot.** Every rendered line — the notice's operator-facing line and the live poke — is
   fixed copy generated by tool code from closed enums. A peer session's model never authors text that
   another session's model then reads as content. This is the decisive prompt-injection mitigation; its
   residual is named in Anti-choice, not claimed closed.

3. **Advisory-only, never a proxy.** A notice may report that an authoritative fact exists ("PR #N merged");
   it may never *be* that fact. It can never satisfy or stand in for operator approval, a permission prompt,
   `guardrail-ack`, a review or QA attestation, merge eligibility, exact integration-candidate freshness
   (eADR-0021 / #915), canon or specification authority, credentials, or deployment authority. The receiver
   verifies the authoritative surface. This is enforced mechanically: coordination code contains no merge
   call, no label write, no commit-status write, and no issue-body edit.

4. **Bounded emission, no broadcast.** Notices are emitted only at semantically meaningful lifecycle points,
   never per file edit and never on a timer. Emission is deduplicated on the structured condition; a live
   poke fires only on a durable-board change; emission is single-attempt and fire-and-forget, and can never
   block, fail, or alter the behaviour of the lifecycle step it rides.

5. **Repo-native identifiers only on durable surfaces.** A durable notice carries only
   repository-native facts — pull request and issue numbers, branch names, commit SHAs, tool and event
   names, timestamps. Worktree paths, machine names, and session identifiers never reach GitHub; they live
   only in the ephemeral live lane and the gitignored local ledger.

6. **Ephemeral bookkeeping, never a corpus.** Read/unread cursors and bounded measurement metadata live in a
   gitignored local ledger, fingerprinting the structured condition and failing toward showing more. Full
   peer exchanges never become a second permanent knowledge store; a future session reconstructs project and
   Engine truth without any coordination-message history.

7. **A sanctioned message lane, not a relaxed non-interference norm.** Peer non-interference over the
   *filesystem* stays absolute — a session never sweeps or edits a peer's worktree. This decision opens a
   *message* lane only: typed, advisory, bounded, and carrying no authority over the receiver.

## Significance

This is the coordination layer that sits on the concurrency law (eADR-0042) and the intra-Build worker DAG
(eADR-0041) without weakening either. Later work must keep coordination advisory: any future notice kind,
emitter, or provider adapter inherits all seven properties, and no adapter may widen what a message can cause
beyond "prompt a peer to re-check canonical state." The provider-neutral shape means a runtime with no live
messaging remains fully first-class through the durable lane alone.

## Rationale

Concurrent sessions already make the repository multi-writer (eADR-0042); until they can signal each other
while active, the human operator is the routine message bus and overlapping or dependent work is discovered
only at reconciliation — safe but late. Coordination removes that lag. It must be advisory because delivery
is genuinely unreliable across runtimes and refusable by design, so any correctness resting on it would be
false consent of exactly the kind the freshness floor (eADR-0021) exists to refuse. The payload is durable on
GitHub because that surface already carries platform-stamped attribution and outlives every session; the
doorbell is live because latency is the only thing live delivery can safely add. This is a new decision
domain — eADR-0041 owns coordination *inside* one Build, eADR-0042 owns *integration* across builds; neither
governs *advisory messaging* across active sessions — so it is a new founding record rather than an overload
of either.

## Anti-choice

Rejected: a general chat channel or workflow engine between sessions. Rejected: a conversational
status-request/reply kind — status is answered by declarative notices plus the live roster, never a
back-and-forth. Rejected: per-file locking or any admission control by overlap — overlap warnings prompt a
human decision, they never gate. Rejected: a free-prose field in a notice or poke — behaviour-driving fields
are closed enums and rendering is fixed tool code, because notice text is ultimately read by a model.
Rejected: steering a peer's *active* turn to deliver advisory traffic — advisory signals never need mid-turn
delivery, so a live adapter uses idle-thread delivery only and never an active-turn steer or a silent
history injection. Rejected: a second session-identity registry — routing identity is the pull request,
derived live from GitHub, because no durable session identity exists and the ephemeral one is
last-writer-wins under concurrency (eADR-0034).

Two residuals are named, not claimed closed: a receiving model still reads a poke as text, so a hostile
message is a prompt injection like any hostile input — bounded by fixed rendering, same-control-plane send
gating, and the standing receiver law that any message is untrusted until canonical state is re-verified; and
any collaborator with repository write can post a comment, so a forged notice is possible — bounded to
harmless because notices carry no authority and the reader skips any that is malformed or fails its digest.
